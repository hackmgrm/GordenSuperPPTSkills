# 质量检查：通过脚本不等于通过视觉验收

## 必须分别记录的四类证据

1. **结构**：layout_guard 严格通过；PPTX 可重新打开；页数、文本数与预期相符；媒体都已嵌入；缺失文件不能跳过。
2. **透明层**：alpha_qa 提供白/灰/黑底合成和前景放大图。查看可见绿/洋红边、黑色残底、缺角、锯齿、色彩污染和细线断裂。透明区在查看器显示为黑色不等于残底，要查 alpha。
3. **视觉与内容**：源图与最终整页并排检查，再放大品牌区、分隔线、文字密集区和图标。检查背景是否残留旧元素、是否双重线条、文本换行/遮挡/缺字、数字/代码/单位是否准确。像素差只作定位，不自动判定语义正确。
4. **实际应用**：可用时用 PowerPoint/LibreOffice 打开并渲染，检查字体替换、文本溢出及编辑行为。Pillow预览必须标记 approximate，不得称为实际PPT渲染。没做就写 not_run，不能写 pass。

可用 `qa-summary.json` 分别记录上述 status（pass / fail / not_run / needs_review）、证据路径和未解决项。截图或报告必须实际生成并查看，不能只写模板式通过。

## 透明层脚本的边界

`alpha_qa.py` 检查是否有 alpha、是否完全空白/不透明，并标记接近所选色键的可见像素及邻近透明区的色键偏色。它不能证明没有细微色差或缺失元素。合法绿色/洋红内容可能触发，需要结合源图审核；不要为通过检测自动修改所有绿色像素。原本就是不透明的照片背景不运行该检查。

每个需要透明的图层都检查；图标网格还要查看切片，保留留白和阴影。全页缩略图容易隐藏1–2像素边缘问题，应在100%和放大视图检查。

## 回归用例

- 深色封面只有横/竖两根金线：应得到两个独立原生对象，不生成空框架/图标层；透明色键图不得出现。
- 复杂光效框架：用图片层，分别叠白/灰/黑底检查，不为去边破坏光效。
- 内容本身含绿：换色键或直接透明输出，不把绿色产品图标去掉。
- 多行中文文字：设置的 line_spacing 应影响近似预览和PPT；实际换行仍以办公软件渲染为准。
- 移动输出文件夹：相对素材路径仍能合成，不依赖原机器绝对路径。

修复后重新检查受影响的页和图层，不机械地重新生成整本。

## 真实办公软件渲染

环境有 `soffice` 和 `pdftoppm` 时运行：

```bash
python3 scripts/render_office.py editable.pptx --out-dir qa/office
# 若渲染器不能发现本机字体，显式传入实际存在的目录，例如macOS：
python3 scripts/render_office.py editable.pptx --out-dir qa/office --font-dir /System/Library/Fonts/Supplemental
```

必须打开生成的PNG。字体在Pillow或系统字体列表里存在，不保证LibreOffice进程能发现它；大标题变成衬线字/换行时先核对渲染器字体搜索路径。不要通过缩小字号来掩盖字体替换。修复字体后根据真实基线回校文本，重新检查分隔线间距、标点是否掉到下一行。无阴影的原生形状同时清除显式与主题效果，避免Impress额外显示投影。

工具缺失时记录not_run；不能把近似预览重命名为真实渲染。不能用原图覆盖页面来通过视觉检查。

### 目标应用字体复核

系统安装了字体、LibreOffice显示正常，也不保证WPS或PowerPoint的字距一致。用户指定应用时，必须在该应用打开最终PPTX检查大标题的字间距、换行和基线。出现字形挤压时，选择在目标应用实测稳定的替代字体并重新校准布局，记录字体变化；不要把测试候选版当作最终验证证据。未在Microsoft PowerPoint验证时明确说明。
