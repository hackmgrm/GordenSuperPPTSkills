# GordenImage2PPTX

目标是忠实、清晰、可维护的还原。默认采用**混合还原**，按元素选择表示方式，不按页强制凑齐四张图片。

## 元素选择

| 元素 | 默认方式 |
|---|---|
| 普通文字，包括航司代码、纯色加粗标题 | 原生文本框；只有字体无法表达的纹理、变形、笔刷等才归艺术字 |
| 直线、纯色矩形、简单圆角卡片、圆形、基础箭头 | 原生 `shapes[]`，可独立修改位置、颜色和尺寸 |
| 纯色页面背景 | 原生 `background_color` |
| 照片、复杂渐变/纹理背景 | imagegen 参考当前源图生成干净背景 |
| 复杂框架、光效、插画、纹理艺术字 | imagegen 生成图片层；工具支持时优先直接透明输出，否则色键去底 |
| 已提供的正式 LOGO、二维码、独立照片 | 使用用户原文件，不重新生成品牌标识或可扫描二维码 |
| 图表 | 有明确数据且要求数据可编辑时使用支持原生图表的工具；不能从模糊图片猜数值；本合成器不支持原生图表 |

用户明确要“原版四层/纯图片层”时使用原版模式：存在的复杂框架与图标用图片，不用原生形状替代；没有对应元素就记录 `not_applicable`，不生成空图。用户要求完全原生可编辑时，先判断当前工具能否实现，准确说明复杂图片部分的限制。

## 执行

1. 读当前源图，创建唯一 `RUN_ROOT`。用户明确续做旧任务时可读取其指定素材；不要搜索相似历史页替代当前源图。
2. 按 [还原流程与 schema](references/image-to-pptx.md) 建立元素清单，标明 native/image/原始资产及原因，确保每个元素只出现一次。先完整做好一张代表页再扩展整本。
3. 仅生成需要的图片层。必须实际传入源图作为编辑目标；提示词中的路径不能替代传图。保留生成原图、提示词与来源记录。
4. 定位文字、图片和原生形状。统一使用源图像素测量，保存 `source_bbox`，再换算坐标；不要混用缩略图坐标。先定字体/字号/行距，再校准位置。
5. 运行 `layout_guard.py --strict`，为透明图运行 `alpha_qa.py`，再合成 PPTX 与预览。按 [质量检查](references/quality-checks.md) 检查并修正，不能把脚本返回 0 解释为视觉合格。
6. 交付 PPTX、源图、实际使用的图层、layout、来源记录和 QA 结论。明确哪些是文本/形状，哪些只是可移动图片，以及是否在真实办公软件中验证。

## 不变量

- 不把含文字的整页源图放到底层再叠同样文字；背景必须去掉已重建的文字、形状和图标。
- 生成的复杂图片层必须来自图像工具；原生对象如实记录为 native，不能伪造 imagegen 证据。代码可以合成、抠图、切分生成的图标表和制作 QA 视图，不能冒充图像模型生成。
- 按用户原文校对品牌、数字、产品代码、机场代码和单位。不清楚的字符复看或询问，不猜造。
- 不从整页源图裁小块冒充重新提取的复杂资产；用户提供的独立资产可直接复用。
- 背景、框架和独立图标的归属要互斥。原生重建的线条必须从生成的背景/框架中移除，避免重影。
- 保留上游署名；不要承诺“完全可编辑”“绝不褪色”或“完美复刻”。

运行时不确定时才读 [runtime-notes.md](references/runtime-notes.md)。
